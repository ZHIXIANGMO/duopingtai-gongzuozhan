# 数据契约.md · 实体、字段与接口

> 从 AGENTS.md 拆出的技术参考（2026-11-01）。**改数据层、写代码对接接口前必读。**
> 设计意图（为什么这么设计）见 [../规划.md](../规划.md) 第 2–3 节；和代码不一致时以 `serve.py` 为准。

## 1. 六层实体，别压平

```
灵感 ──孵化──> 选题 ──衍生──> 稿件 ──投放──> 投放记录
```

- **一个选题可以喂给两个身份** → 两篇独立稿，语言和切口都不同
- **一篇稿可以投两个号** → 两条独立投放记录，各改各的开头
- **账号 = 身份 × 平台**，这是核心。不是"账号有个平台标签"那么简单
- **同一身份 × 同一平台可以有多条账号记录**（主号 / 小号 / 测试号），互不干扰。
  所以「身份 + 平台」不是唯一键，`账号.id` 才是。写代码时不要假设一格只能放一个号

上一版把选题、正文、渠道、阅读量塞进一个 `001.md`，多账号一进来就废了。别退回去。

## 2. 人设是两层，不是一层

「身份」不是几个标签，是**一整个人的说明书**。读者是 AI，不是访客——
所以人设页默认只读，编辑入口收在每个区块右上角的一个按钮里，点开弹窗只改这一块。
**不要把输入框铺满整页**：那是人来看的地方，不是填表的地方。

| 层 | 放哪 | 装什么 | 谁在改 |
|---|---|---|---|
| 短字段 | frontmatter | 头像 / 一句话 / 年龄 / 生日 / 定位 / 领域 / 读者 / 语气 | 人设页的输入框 |
| 长文本 | 正文的 8 个 `##` 小节 | 这个人是谁 / 要传递什么 / 说话方式 / 模仿样例 / 写作习惯 / 视觉与设计风格 / 平台差异 / 别做的事 | 人设页的文本域 |

- 小节名写死在 `serve.py` 的 `PERSONA_SECTIONS`，**顺序和字面都不能改**——
  页面靠标题定位，改一个字那一节就读不出来。空小节留标题不写内容即可。
- **小节内容里不能有 `#` 标题行**。一个 `## xxx` 会被人设文件当成新小节，整篇结构就散了。
  人设页读入时把标题压成 `**加粗**`，`save_section()` 里 `flatten_heads()` 兜底——别绕过它。
- **不许往人设文件里写「待补」之类的占位**。`build_persona()` 把空小节翻译成
  「还没填的：xxx」，让 AI 知道缺什么、来问用户。写占位符就变成"有内容"，AI 会当真。
- `build_persona()` 把两层拼成六块喂给模型，最后附缺项清单。
  **人设写多细，AI 就多像你**——唯一直接影响输出质量的输入。
- AI 的立场写在 `BASE_RULES`：跟用户讨论时是助手，开始写要发出去的正文
  就切换成这个身份本人（"不是模仿他，是就是他"）。

## 3. frontmatter 规则

解析器只认扁平的 `key: value`，**不支持嵌套、数组、多行值**。
字段顺序由 `serve.py` 的 `ORDER` 常量固定，写回时按那个排。新字段加在后面，别插到前面。

## 4. 枚举值

| 字段 | 允许值 |
|---|---|
| 选题.状态 | `待定` / `已定` / `已用` / `废弃` |
| 稿件.阶段 | `讨论` / `正文` / `配图` / `排版` |
| 稿件.配图形式 | `公众号` / `小红书` / `不配图`（默认公众号，三选一）|
| 灵感.状态 | `未孵化` / `已孵化` / `已废弃` |
| 账号.平台 | `小红书` / `公众号` / `抖音` / `B站` |
| 优先级 | `P0` / `P1` / `P2` |

`稿件.阶段 = 正文` 会自动进首页待办（"正文等你过目"）。
旧文件的 `稿件.状态` 已被 `阶段` 取代，`LEGACY_STAGE` 留了读时兜底
（构思→讨论；初稿/打磨/待审/待确认→正文；定稿→排版；复盘→排版），别再把 `状态` 写回去。

## 5. 四阶段怎么走

```
选题与讨论 ──> 正文 ──> 配图 ──> 排版与发布
    ↑           ↑        ↑
    └───────────┴────────┘  往回点 = 退回
```

- 阶段值存在 frontmatter 的 `阶段` 字段，顺序定义在 `serve.py` 的 `STAGES`，**改这里前端跟着变**
- 每格对应正文里一个 `##` 小节：`配图` / `排版`（见 `STAGE_SECTION`）。讨论格没有产物，「素材」那一节只是素材，不算阶段产物
- **只有白名单里的 `##` 才算小节**（`KNOWN_SECTIONS`）。正文里写 `## 早上那一小时` 是文章小标题，
  不是小节边界。老写法按所有 `##` 切，会把正文切碎、还不报错。加新小节时**必须同时改前后端两个白名单**
  （`serve.py` 的 `KNOWN_SECTIONS` 和 `draft.html` 的同名常量）
- **什么算「有产物」**（`has_product()`）：配图和排版不靠小节记——配图写 `配图形式` 字段，排版写 `排版` 字段
  （复制排版时自动写入，如 `16px · 行距 1.9 · 字距 0px · 纸白 · 电脑看`）。
  只看 `##` 小节的话这两格永远是空的，退回时也就永远不提示待重做
- **退回**：点前面某格，`STAGES` 里该格之后的、已经有产物的阶段进 `重做` 字段（如 `重做: 配图,排版`），
  内容先留着给人看，但界面标红提示「待重做」
- **回来**：再次进入那一格时，旧内容挪进 `数据/.历史/作废/<id>.<阶段>.<时间>.md`，小节清空，重新开一版
- **改正文也会触发**：`save_entity` 发现正文变了，会把当前阶段及之后有产物的阶段都标进 `重做`。
  这是"配图时发现正文有问题，回去改"那条路的实现，别绕过它
- **往回点必弹确认**：`askBack()` 出一个和页面同风格的弹窗（不用原生 `confirm`），写明哪几格会作废。
  有产物时点「确定退回」才走；没产物时说"后面几格还没做过什么"。
  进度条每格下面写明阶段名（`stageBar(d,{labels:true})`），只有稿件窗口开；首页和选题页空间小，不带标签

## 6. 冲突四格与初稿

`正方 / 反方 / 我站 / 我可能错在哪`，四个都填得出这个题才硬。
任一是空、`待补`、`无`，选题会顶到待办最前面。

2026-11-01 用户新增要求：人设和灵感设置后即可生成初稿。因此冲突四格继续用于打磨与待办提示，**不阻止初稿生成**；模型不得代编用户立场、经历和数字，缺失事实要省略或明确标待补。

## 7. 投放.csv

```
id,发布日,标题,稿件,账号,适配说明,链接,阅读,点赞,收藏,评论,涨粉,更新于,推广动作,推广结果
```

- 一行 = 一次发布。`互动` / `互动率` 不存，服务端现算
- 读用 `utf-8-sig`，写也带 BOM（用户会用 Excel 打开）
- 同账号 + 同日期 + 同标题 = 覆盖，不重复（`add_pub` 里判断）
- `更新于` 超过 7 天会被标「该刷了」

## 8. 日志.csv

```
时间,日期,类型,对象,动作,备注
```

- 一行 = 一件事。`类型` 现在是 `阶段` / `正文` / `产物` / `开稿`
- 首页日历按 `日期` 数条数分深浅（0 / 1 / 2–3 / 4+ 四档）
- 只追加不改写。`read_logs()` 返回按时间倒序的最新 400 条
- 日志写失败不挡业务（`append_log` 吞掉 OSError）

## 9. 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/state` | 一次返回全部：五类实体 + 投放 + 待办 + 统计 + AI 状态 |
| GET | `/api/persona` | 人设页专用。`?id=per-01` 只给这一个身份 + 小节内容 + 完整度 |
| GET / POST | `/api/settings` | 读/保存模型列表、当前模型、技能指令。GET 仅返回密钥是否已配置，不返回密钥；POST 密钥留空保持原值，改接口需重新填密钥 |
| POST | `/api/model_test` | 向已保存的当前模型发送简短请求，不发送人设或稿件 |
| POST | `/api/spark_draft` | `{灵感,身份}` 创建关联选题与稿件；再次点击复用同一身份已有稿件 |
| POST | `/api/generate` | `{kind:"稿件",id,要求}` 按稿件绑定的人设生成纯 Markdown，SSE done 带 revision；不写正文 |
| POST | `/api/adopt_draft` | `{id,正文,revision}` 人工采用；版本不一致拒绝，保留旧稿历史，讨论阶段推进至正文 |
| POST | `/api/chat` | SSE 流式对话。`{kind,id,messages}` |
| POST | `/api/write` | `{kind,id,字段,正文}` 写回 md。`kind` 也可以是「身份」。**`正文` 是整篇替换**，会覆盖所有小节，别拿它改文章，用 `/api/section` |
| POST | `/api/section` | `{kind,id,小节,内容}` 只替换一个 `##` 小节，别的小节原样留着。人设页按块编辑走这个 |
| POST | `/api/pub` | 手填/外部推送一条投放 |
| POST | `/api/stage` | `{kind:"稿件",id,阶段,说明}` 推进/退回阶段。退回时把下游标待重做，重进时清空重开 |
| POST | `/api/asset` | `{稿件,名字,数据}` 拖进来的文件，数据是 base64。落 `数据/素材/<稿号>/` |
| POST | `/api/new` | `{kind, 其它字段}` 建一条空壳。`灵感`（原话）、`选题`（标题候选）、`账号`（平台+账号名）。页面上「＋」走这个 |
| POST | `/api/new_draft` | `{选题,身份}` 从一条选题开一篇新稿，落在 `讨论`，id 按目录里最大号往下排 |
| POST | `/api/ingest` | 书签脚本专用，必须带 `令牌` |

- `/api/state` 是唯一的数据入口，前端不做多次请求。统计全部现算，页面里不许硬编码数字
- 写盘前 `snapshot()` 会在 `数据/.历史/<类型>/` 存一份旧文件，每份留最近 20 版，改坏了能捞回来

## 10. AI 改文件的方式（应用内对话）

AI 不能直接写文件。它在回答末尾输出：

```json
{"写入":[{"kind":"选题","id":"tp-001","字段":{"反方":"改后的内容"}}]}
```

改整篇正文要放**顶层 `正文`**，不要塞进 `字段`：

```json
{"写入":[{"kind":"稿件","id":"dr-001","正文":"整篇文章，Markdown"}]}
```

服务端 `extract_writes()` 两种形态都认（顶层和 `字段.正文`），前端把正文转给 `/api/section` 只替换「## 正文」一节，
不会抹掉素材/配图/排版。**千万别把正文走 `/api/write` 的 `body` 参数**，那是整篇替换。

服务端用正则捞出这个块，前端渲染成「AI 想改 N 处 → 应用」按钮。**用户点了才落盘。**
这个设计是刻意的：任何 AI 改动都要过一次人工确认。

## 11. AI 的硬规则（写在 `serve.py` 的 `BASE_RULES` 里）

1. 不许编 —— 稿件细节只能来自「必须写进去的细节」，缺就提问
2. 不许客套
3. 一次只推进一步
4. 说人话，不用「赋能/闭环/抓手」
5. 改文件必须走上面那个 json 块

独立初稿生成使用 `generation_messages()`，只返回文章预览，经 `/api/adopt_draft` 人工确认。普通对话仍用 JSON 写入块。

## 12. 模型与写作技能

- `.env` 的 `DSH_AI_CONFIG` 保存 `模型列表` 与 `当前模型`，值是 JSON 编码的字符串。每个模型有 `id/名称/接口/模型名/api_key/代理/技能`，`技能` 是启用的技能 ID 列表。旧 `本地配置.json` 启动时校验迁移，再清理旧副本。
- `.env` 的 `DSH_LOCAL_SETTINGS` 保存原本的本地设置及书签令牌；保留未知机密变量。文件损坏或旧配置与 `.env` 冲突时拒绝覆盖。测试账号、人设和文章不迁移，继续使用 Markdown。
- `数据/技能/<id>.md` 是技能真源：frontmatter 为 `id/名称`，正文是写作指令。页面可导入 Markdown 或直接编辑；不运行脚本、不加载关联文件、不自动安装 Agent Skill。
- 技能随当前模型用于生成和普通对话；人设取稿件绑定身份，不能被侧栏切换误替换。样例只学表达，不当作当前文章的事实来源。
- 保存立即生效。配置及技能均受现有 gitignore 保护；静态 HTTP 禁止读取配置、源码、历史与私人原文。写接口校验同源及 JSON，书签接口保留令牌机制。
