# 页面结构草案

> 2026-11-02 · 实施计划第 1 步。可交互草案已制作，尚待用户确认。不是正式业务实现。

预览：`http://127.0.0.1:8777/assets/prototype/index.html`。
源码：`assets/prototype/index.html`、`prototype.css`、`prototype.js`。

## 1. 页面结构

```text
总览
├─ IP 与平台账号信息表
├─ 还没完成的文章（准备写 / 正在写 / 待分发）
├─ 选题储备
└─ 开始写文章 → 选择 IP、说想法 → 文章页

某个 IP
├─ 赛道、目标读者、语言风格
├─ 文章列表与进度筛选
├─ 选题储备 → 开始聊这篇
└─ 开始写文章

某篇文章
├─ 正文与讨论 / 配图 / 排版与分发（只切换查看）
├─ 当前母稿（可直接编辑） │ 围绕这篇的聊天与拟写建议
├─ 正文确认 → 配图确认 → 平台分发准备
└─ 各目标账号独立排版和发布状态，仍关联同一母稿
```

首页回答“我有哪些 IP 和账号，哪些文章还没完成”。IP 视图回答“这个 IP 接下来写什么”。文章页回答“怎样把这篇写好、做完”。正式版仍可保留已有设置、人设及详细数据入口，但不在结构原型中堆上全部旧导航；具体入口随用户反馈确定。

## 2. 草案可操作的部分

- 首页进入 IP、文章；开始一篇演示文章；从 IP 选题开始聊。
- IP 文章按准备写、正在写、待分发筛选，数量由演示数据计算。
- 同屏编辑母稿与聊天，展示固定的演示建议；采用前母稿不变。
- 展示建议后再修改正文，建议显示过期并禁止应用。
- 确认正文后导入本机图片预览；确认图片后查看两个平台的分发位置。
- 点击配图、排版只查看；未经用户确认，不跳过正文和图片审核。
- 窄屏切换文章和聊天，桌面同时展开。

## 3. 演示边界

不读取正式 API，不读取用户的 IP 文件或稿件，不保存到磁盘，不调用模型或执行发布。页面刷新重置演示数据。图像使用浏览器临时地址，不上传。

IP 名“橘子头”“这么说”来自需求举例；平台归属、文章标题、正文和选题均用于结构演示，不代表用户真实运营配置或个人表达。赛道和读者显示待填写，运营数据显示缺失值。新建文章的正式流程仍必须先补齐赛道与读者。

聊天中明确标注固定建议，不能将此草案验收计为真实 AI 写作能力验收。平台预览仅显示后续能力的位置，不算完整排版。发布尚未实现。

## 4. 设计取舍

- 沿用现有中性灰白、中文系统字体和单一红色强调，不引入字体、依赖或图片装饰。
- 使用 Framed sheet 结构（种子 1589323018），让侧栏退到背景，内容在一张白色工作面上。
- 首次工具抽到暗色样式，与项目既有亮色规范冲突，因此调整为亮色；不据工具建议替换用户要求的信息表。
- 识别本产品的主要元素是“当前母稿与对话共同展开”，不是数据图表。账号数据用表格，避免无数据的图表占据主视图。
- 草案初期不做日历和复杂待办，先让用户判断文章与 IP 的主次。

## 5. 验收与后续

第 1 步是否完成，取决于用户能否理解从哪里开始、母稿如何与聊天配合、确认动作如何推进。用户尚未确认，不开始第二步的数据迁移或正式页面替换。

浏览器检查结果在 STATUS.md 记录。确认后整理反馈，再执行实施计划第 2 步。
